SURVEILLANCE ROVER PROJECT RUNBOOK
===================================

Purpose
-------
This document contains the complete setup, deployment, operation, and
troubleshooting procedure for the ESP32 + Raspberry Pi rover system.
Update this file whenever the project workflow changes.

---------------------------
The Raspberry Pi now hosts the rover Wi-Fi "TAPIR" (Pi 192.168.50.1, ESP32

System architecture
-------------------
Laptop (vision app, http://127.0.0.1:8090/)
    |   ^
    |   | camera stream  GET /camera
    |   |
    | follow + manual commands  HTTP :8080
    v   |
Raspberry Pi gateway (USB webcam, manual dashboard)
    |
    | HTTP :80
    v
ESP32 web server
    |
    +-- Motors
    +-- GPS

The ESP32 controls motors, timed movement, watchdog stopping, and GPS.
The Raspberry Pi streams the USB webcam, hosts the manual driving
dashboard, and forwards commands to the ESP32. No video processing runs on
the Pi.
The laptop reads the Pi's camera stream, runs human body detection and face
recognition, and in follow mode steers the rover towards a detected person
by sending commands through the Pi.

PART 1 - ESP32 HARDWARE AND WIRING
===================================

Motor pins from src/config.h
----------------------------
Left BTS7960:
  LEFT_RPWM = 25
  LEFT_LPWM = 26

Right BTS7960:
  RIGHT_RPWM = 27
  RIGHT_LPWM = 14

GPS GY-NEO6MV2 on ESP32 UART2:
  GPS_RX_PIN = 16 (connect to GPS TX)
  GPS_TX_PIN = 17 (connect to GPS RX)
  Baud rate  = 9600

Before powering the rover:
1. Connect ESP32 GND, motor driver GND, and GPS GND together.
2. Confirm motor driver power wiring and current rating.
3. Keep wheels lifted during the first motor test.
4. Confirm the GPS TX/RX connections are crossed correctly.
5. Keep the physical emergency stop accessible.

PART 2 - ESP32 WIFI CONFIGURATION
==================================

Open the ESP32 project:

PowerShell on the development computer:

  cd "D:\Desktop\Hackathon\ESP32 human detection\RadarTest"

Edit src/config.h and set the Wi-Fi network shared by the ESP32, Pi,
and laptop:

  const char *const WIFI_AP_SSID = "ESP32-Robot";
  const char *const WIFI_AP_PASSWORD = "<choose a strong password>";

Keep the real password out of Git. Anyone who joins this network can drive
the rover from the dashboard.

The ESP32 creates this network; no external router or phone hotspot is needed.

The access point is:

  SSID:     ESP32-Robot
  Password: (set in src/config.h, not recorded here)
  ESP32 IP: 192.168.4.1

The ESP32 access point is the primary network. Connect the Pi, laptop, and
phone camera to ESP32-Robot. The ESP32 address is fixed at 192.168.4.1.

The Pi uses fixed address 192.168.4.10 on the ESP32 access-point network.
No router, DHCP reservation, or mDNS is required.

PART 3 - BUILD, UPLOAD, AND FIND ESP32 IP
==========================================

Build the ESP32 firmware:

  cd "D:\Desktop\Hackathon\ESP32 human detection\RadarTest"
  pio run

Find the serial port on Windows:

  pio device list

Upload, replacing COMx with the actual port:

  pio run --target upload --upload-port COMx

Open the serial monitor:

  pio device monitor -b 115200

Press the ESP32 reset button. Look for one of these messages:

  Rover Wi-Fi AP: ESP32-Robot
  Dashboard: http://192.168.4.1

Record the printed ESP32 address for the Pi configuration.

Test the ESP32 from the Pi:

  curl --max-time 5 http://ESP32_IP/api/status

Example:

  curl --max-time 5 http://192.168.4.1/api/status

Expected response shape:

  {"wifi":"192.168.4.1","ap":true,"motionActive":false,"gps":{"fix":false,"latitude":0.000000,"longitude":0.000000,"altitude":0.0,"satellites":0}}

PART 4 - CREATE OR UPDATE THE RASPBERRY PI REPOSITORY
======================================================

Repository:

  https://github.com/aadityapranav989-ai/surveillance-rover_PI.git

SSH into the headless Pi:

  ssh pi@raspberrypi.local

If the hostname is unavailable, find the Pi address from the router or use
the address shown by hostname -I, then connect with:

  ssh pi@PI_IP

Install prerequisites:

  sudo apt update
  sudo apt install -y git python3 python3-venv v4l-utils avahi-daemon libnss-mdns

Clone the repository. Use this only on a new installation:

  sudo mkdir -p /opt
  sudo git clone https://github.com/aadityapranav989-ai/surveillance-rover_PI.git /opt/raspberry-pi-rover
  sudo chown -R pi:pi /opt/raspberry-pi-rover

For an existing installation, update instead:

  cd /opt/raspberry-pi-rover
  git pull --ff-only

Create the Python environment. This needs internet access, so do it while
the Pi is on a normal Wi-Fi network, before switching it to ESP32-Robot.
Re-run the pip line after pulling changes to requirements.txt:

  cd /opt/raspberry-pi-rover
  python3 -m venv .venv
  .venv/bin/pip install -r requirements.txt

The Pi uses OpenCV only to read and encode webcam frames; it does not need
the vision models. The systemd service runs
/opt/raspberry-pi-rover/.venv/bin/python, so the .venv must exist before the
service starts.

PART 5 - CONFIGURE THE PI GATEWAY
==================================

Create the systemd environment configuration:

  sudo tee /etc/default/rover-dashboard >/dev/null <<'EOF'
ESP32_URL=http://192.168.4.1
CAMERA_DEVICE=/dev/video0
CAMERA_WIDTH=640
CAMERA_HEIGHT=480
CAMERA_FPS=30
JPEG_QUALITY=60
ROVER_HOST=0.0.0.0
ROVER_PORT=8080
EOF

All settings and defaults are listed in config.py.

Configure the Pi Wi-Fi connection with fixed address 192.168.4.10:

  nmcli connection show --active
  sudo nmcli connection modify "WIFI_CONNECTION_NAME" ipv4.method manual ipv4.addresses 192.168.4.10/24 ipv4.gateway 192.168.4.1 ipv4.dns 192.168.4.1
  sudo nmcli connection down "WIFI_CONNECTION_NAME"
  sudo nmcli connection up "WIFI_CONNECTION_NAME"
  hostname -I

Verify from the Pi:

  curl --max-time 5 http://192.168.4.1/api/status

USB webcam:

  v4l2-ctl --list-devices
  v4l2-ctl --list-formats-ext -d /dev/video0

The Pi opens the webcam once and shares it with every viewer, including the
laptop vision app. The raw stream is served at /camera. Configure these
values only if the webcam device or format changes:

  CAMERA_DEVICE=/dev/video0
  CAMERA_WIDTH=640
  CAMERA_HEIGHT=480
  CAMERA_FPS=30
  JPEG_QUALITY=60

The stream crosses the ESP32 Wi-Fi, which has limited bandwidth. The Pi
skips frames the Wi-Fi can't carry instead of queueing them, so the video
stays live. The service log shows the webcam mode, for example
"(640x480 MJPG @ 30 fps)". If it says YUYV at 5 fps, the webcam has no MJPG
mode. For a smoother picture, lower JPEG_QUALITY (for example 50) and
restart the service:

  sudo systemctl restart rover-dashboard

The Pi dashboard shows "Laptop follow mode: DRIVING / idle / blocked" so the
person at the Pi dashboard can see when the laptop is steering.

Joystick navigation:

  Up       = forward
  Down     = backward
  Left     = left turn
  Right    = right turn

The virtual joystick sends one short ESP32 motion command every 150 ms while
held, with at most one request in flight.
Releasing the joystick, changing browser focus, or pressing STOP sends the
stop command. Test with the wheels lifted before placing the rover on the
ground.

Install or refresh the systemd service:

  sudo cp /opt/raspberry-pi-rover/systemd/rover-dashboard.service /etc/systemd/system/
  sudo systemctl daemon-reload
  sudo systemctl enable --now rover-dashboard

After changing /etc/default/rover-dashboard:

  sudo systemctl restart rover-dashboard

Check service status:

  sudo systemctl status rover-dashboard

Expected state:

  Active: active (running)

Confirm the Pi is listening:

  sudo ss -tulpn | grep 8080

Expected shape:

  tcp LISTEN 0 5 0.0.0.0:8080 0.0.0.0:* users:(...(python3...))

PART 5B - LAPTOP VISION (BODY DETECTION, FACE RECOGNITION, FOLLOW)
====================================================================

One-time install on the laptop, while it has internet access (PowerShell):

  git clone https://github.com/aadityapranav989-ai/surveillance-rover_PI.git
  cd surveillance-rover_PI
  python -m venv .venv
  .venv\Scripts\pip install -r requirements.txt
  .venv\Scripts\python scripts\download_models.py
  .venv\Scripts\python -m unittest discover -s tests

Run it:

  1. Join the laptop to ESP32-Robot.
  2. Confirm the Pi dashboard opens at http://192.168.4.10:8080/.
  3. Start the vision app:

       powershell -ExecutionPolicy Bypass -File scripts\run_laptop.ps1

  4. Open http://127.0.0.1:8090/ on the laptop.

The laptop dashboard shows the annotated camera: bodies in green, recognized
faces in blue with their name, unknown faces in red, and the follow target in
yellow. If it shows "hog" as the body detector or face recognition "off", run
scripts\download_models.py again.

Set follow tuning such as FOLLOW_MAX_SPEED as environment variables in the
same PowerShell window before running the script, for example:

  $env:FOLLOW_MAX_SPEED = "120"

All follow settings are listed and explained in config.py.

Enroll faces:

  - Under "Known faces": one person in view, facing the camera, 3-5 photos
    from different angles. Photos are stored on the laptop in
    faces\<name>\ and are never committed to Git.
  - Only enroll people who have agreed to it.

Follow mode:

  - Under "Follow a person", choose Anyone or a named person and press
    Start following. The rover turns towards the target, drives forward
    while the target is far, and stops when the target is close or lost.
  - STOP or any manual drive command on either dashboard ends follow mode.
    The Pi then refuses follow commands until Start following is pressed
    again on the laptop.
  - If the laptop disconnects, the rover completes its last short step and
    stops.
  - Test follow mode with the wheels lifted first, then in an open area with
    a low FOLLOW_MAX_SPEED.

PART 7 - TEST THE SYSTEM HEADLESS
==================================

Run these commands on the Pi.

Test ESP32 connectivity:

  ping -c 4 -W 2 192.168.4.1
  curl --max-time 5 -v http://192.168.4.1/api/status

Test the Pi gateway locally:

  curl --max-time 5 http://127.0.0.1:8080/api/status

Test the gateway from another computer:

  curl --max-time 5 http://PI_IP:8080/api/status

Send a forward command. Keep the first test short and keep the wheels lifted:

  curl -X POST "http://PI_IP:8080/api/command?direction=FORWARD&speed=80&value=5"

Send a left turn:

  curl -X POST "http://PI_IP:8080/api/command?direction=LEFT&speed=80&value=10"

Stop immediately:

  curl -X POST http://PI_IP:8080/api/stop

The value is distance in centimeters for FORWARD/BACKWARD and degrees for
LEFT/RIGHT. Speed is from 1 to 255.

PART 9 - TROUBLESHOOTING
=========================

Symptom: curl to 192.168.4.1 hangs or times out

Cause: the Pi is not connected to the ESP32 access point.

Check the Pi network:

  ip route
  hostname -I

The Pi should have 192.168.4.10 and the ESP32 should have 192.168.4.1. Update
the Pi Wi-Fi connection if needed:

  sudo nano /etc/default/rover-dashboard
  sudo systemctl restart rover-dashboard

Symptom: ESP32 unavailable from the Pi

  ping -c 4 -W 2 ESP32_IP
  curl --max-time 5 -v http://ESP32_IP/api/status
  sudo systemctl status rover-dashboard
  journalctl -u rover-dashboard -n 50 --no-pager

Confirm ESP32 and Pi are on the same subnet: 192.168.4.x.

Symptom: dashboard opens but GPS says waiting for fix

1. Move the GPS antenna outdoors or near an unobstructed window.
2. Confirm GPS TX is connected to ESP32 GPIO16.
3. Confirm GPS RX is connected to ESP32 GPIO17.
4. Confirm the module uses 9600 baud.
5. Watch the ESP32 serial monitor for GPS output.

Symptom: laptop dashboard says "Camera offline"

Check that the laptop is on ESP32-Robot and that
http://192.168.4.10:8080/camera shows video in a browser. If it does, restart
scripts\run_laptop.ps1. If it does not, check the Pi camera below.

Symptom: Pi dashboard says "Camera offline"

  v4l2-ctl --list-devices
  groups pi                (must include video)
  sudo systemctl status rover-dashboard

Only one process on the Pi can open the webcam. Stop any manually started
app.py or other camera program, then restart the service.

Symptom: face shows as "unknown" or the wrong name

Enroll more photos of the person in the rover's real lighting. Raise
FACE_MATCH_THRESHOLD if the wrong name appears; lower it slightly if an
enrolled person stays unknown.

Symptom: SSH says REMOTE HOST IDENTIFICATION HAS CHANGED

Only do this when you know the Pi was reinstalled or its host key changed:

  ssh-keygen -R raspberrypi.local
  ssh pi@raspberrypi.local

Verify the new fingerprint before accepting it.

Symptom: port 8080 is not reachable from the laptop

On the Pi:

  sudo ss -tulpn | grep 8080
  hostname -I
  sudo systemctl status rover-dashboard

If UFW is enabled:

  sudo ufw allow 8080/tcp

PART 10 - UPDATE PROCEDURE
===========================

After changing the Pi repository:

On the development computer:

  cd "D:\Desktop\Hackathon\ESP32 human detection\RaspberryPiRover"
  git add .
  git commit -m "Describe the change"
  git push

On the Pi:

  cd /opt/raspberry-pi-rover
  git pull --ff-only
  .venv/bin/pip install -r requirements.txt
  sudo cp systemd/rover-dashboard.service /etc/systemd/system/
  sudo systemctl daemon-reload
  sudo systemctl restart rover-dashboard
  sudo systemctl status rover-dashboard

After changing ESP32 firmware:

  pio run
  pio run --target upload --upload-port COMx

Then reset the ESP32, read its new Wi-Fi IP from the serial monitor, update
/etc/default/rover-dashboard if needed, and restart the Pi service.
